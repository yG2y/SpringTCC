# TCC 2 — Seleção de repositórios candidatos a Spring Boot

> **Para a reunião:** execução parcial encerrada com **42.317 candidatos coletados e 5.803 elegíveis**. Consulte o [relatório curto](RELATORIO_REUNIAO.md). A coleta do universo completo permanece pendente.

## O que foi feito

Foi preparado um processo em Python para consultar o GitHub, coletar os repositórios encontrados, aplicar filtros com justificativas e selecionar até **50.000 repositórios**, ordenados por estrelas. Cada etapa registra quantos entraram, quantos foram excluídos e quantos permaneceram, além dos nomes e motivos das exclusões.

O objetivo desta etapa é construir uma base de candidatos para a pesquisa. A medição de complexidade com a ferramenta CK é uma etapa posterior.

## 1. Consulta do total

A consulta usada na API de busca de repositórios é:

```text
topic:spring-boot fork:true
```

`topic:spring-boot` encontra repositórios identificados com esse tópico. `fork:true` inclui forks na contagem inicial, permitindo mostrar depois quantos foram removidos. Não foi exigida linguagem Java nem quantidade mínima de estrelas nesta descoberta, para não descartar antecipadamente projetos com várias linguagens.

Em **17/09/2026 às 16:36:06 UTC**, a API retornou **95.666 candidatos**, com `incomplete_results=false`. A contagem anterior, de 16/09/2026, era 95.439. Os números mudam porque o GitHub muda ao longo do tempo.

**Esse é o total retornado para a consulta, não o total comprovado de todos os projetos que usam Spring Boot.** Projetos sem o tópico ficam fora, e ter o tópico não comprova uma dependência no código. A verificação técnica existente procura evidências nos arquivos `pom.xml`, `build.gradle` e `build.gradle.kts` da raiz.

Evidência: [count.json](Instrumentos/Codigos/Artefatos/selecao_spring_boot/runs/20260917_apresentacao/count.json).

## 2. Critérios e justificativas

Os filtros são aplicados na seguinte ordem. Um repositório excluído não entra nas etapas seguintes; assim, não é contado duas vezes nas exclusões.

1. **Excluir forks** (`is_fork=true`): reduzir a repetição de código derivado de um mesmo projeto. Limitação: um fork pode ter evolução própria.
2. **Excluir espelhos** (`is_mirror=true` ou `mirror_url` preenchido): reduzir cópias do mesmo código. A API de busca pode omitir esse campo; zero exclusões não comprova ausência de espelhos.
3. **Excluir arquivados** (`archived=true`): concentrar a análise em projetos que não foram colocados em modo de arquivamento pelo mantenedor. Isso reduz a presença de projetos históricos.
4. **Excluir desabilitados** (`disabled=true`): evitar projetos indisponíveis para análise. A detecção depende do campo fornecido pela API.
5. **Exigir atividade nos últimos três anos**: manter `pushed_at` igual ou posterior à data de `count.json` menos três anos. Nesta execução, o corte é **17/09/2023 às 16:36:06 UTC**. Datas ausentes ou inválidas também são excluídas. A janela de três anos concretiza o recorte de atividade recente proposto para esta etapa e admite projetos com atualizações menos frequentes; não é um limiar que comprove abandono ou manutenção contínua. **Não significa que o projeto tenha sido criado nos últimos três anos.** Projetos antigos com push recente podem permanecer.
6. **Excluir templates** (`is_template=true`): separar modelos para iniciar projetos das aplicações a estudar. O campo pode estar ausente na busca.
7. **Excluir vazios** (`size_kb <= 0` ou sem branch padrão): evitar repositórios sem uma base disponível para análise. Tamanho positivo não garante presença de código Java.
8. **Excluir materiais educacionais ou listas identificados por metadados**: usar os tópicos e expressões de nome definidos no arquivo de configuração. A intenção é reduzir cursos, tutoriais, slides e listas de recursos, que têm finalidade diferente de uma aplicação. É uma classificação heurística, sujeita a erros.

Os tópicos de exclusão automática são: `tutorial`, `tutorials`, `course`, `courses`, `workshop`, `workshops`, `bootcamp`, `bootcamps`, `cheatsheet`, `cheat-sheet`, `cheat-sheets`, `awesome-list`, `awesome`, `slides`, `slideshow`, `lecture`, `lectures`, `mooc`, `udemy` e `exercism`.

As expressões aplicadas ao nome do repositório são:

```text
^awesome-.+
.+-(course|tutorial|workshops?|bootcamps?|cheatsheets?|slides)$
^(course|tutorial|workshop|bootcamp)-.+
```

Sinais ambíguos como `example`, `demo`, `sample` e `learning` no nome apenas geram uma lista para revisão, sem exclusão automática. Termos na descrição, incluindo `textbook` e `lecture notes`, também apenas sinalizam. Portanto, **a remoção de todos os materiais de aula e livros ainda depende de revisão**; o script não lê todos os READMEs nem garante essa classificação.

Os critérios exatos estão em [config.yaml](Instrumentos/Codigos/Artefatos/selecao_spring_boot/runs/20260917_apresentacao/config.used.yaml). São escolhas metodológicas para um recorte de projetos com atividade recente, não regras universais nem critérios ajustados para atingir 50.000. Devem ser conciliados com o desenho longitudinal do artigo, caso ele continue sendo utilizado.

## 3. Ordenação e definição de N

Depois dos filtros, os elegíveis são ordenados por:

1. Maior número de estrelas (`stargazers_count`, decrescente).
2. Em caso de empate, push mais recente (`pushed_at`, decrescente).
3. Persistindo o empate, menor identificador do GitHub (`repository_id`, crescente).

Estrelas foram escolhidas como uma medida observável de popularidade e para permitir uma ordenação objetiva. **Não medem qualidade e não produzem uma amostra aleatória.** Os desempates tornam a ordenação determinística para os mesmos dados.

O limite de **50.000 é um teto operacional solicitado para esta base**, e não um tamanho calculado para garantir representatividade estatística. O tamanho final é **N = mínimo entre 50.000 e o número de elegíveis**. O limite é aplicado só depois da filtragem. Se restarem menos de 50.000, todos os elegíveis são selecionados e os filtros não são relaxados. Se sobrarem mais, o restante fica fora pelo limite da amostra, não por inelegibilidade.

## 4. Scripts e reprodução

Os scripts já separam contagem, descoberta, filtragem, seleção e validação técnica. A API limita a recuperação de cada consulta a 1.000 resultados; por isso, o coletor divide a descoberta por datas de criação e, se necessário, estrelas. Essas divisões servem para coletar a base, não para selecionar projetos mais novos ou mais populares antes dos filtros.

A descoberta cobre 2008 a 2026, evitando omitir repositórios antigos que receberam o tópico posteriormente. Os IDs são usados para evitar duplicações. As janelas concluídas ficam registradas para permitir retomada.

Na pasta `Instrumentos/Codigos/codigoCKSpring`, com as dependências de `requirements.txt` instaladas e `GITHUB_TOKEN` configurado no `.env`:

```powershell
# Processo completo; o mesmo caminho permite retomar a coleta.
python select_spring_boot.py --run-dir ../Artefatos/selecao_spring_boot/runs/20260917_apresentacao --limit 50000 run

# Depois da descoberta, refazer os filtros e a seleção.
python select_spring_boot.py --run-dir ../Artefatos/selecao_spring_boot/runs/20260917_apresentacao --limit 50000 filter

# Verificar os arquivos de build dos 30 primeiros selecionados.
python select_spring_boot.py --run-dir ../Artefatos/selecao_spring_boot/runs/20260917_apresentacao validate --sample-size 30

# Testes automatizados.
python -m unittest discover -s tests -v
```

As opções gerais, como `--run-dir` e `--limit`, devem vir **antes** de `run`, `filter` ou `sample`. Para uma nova coleta independente, use outro diretório de execução.

A validação técnica verifica os primeiros 30 da ordenação, não uma amostra aleatória. Ausência de evidência na raiz não prova ausência de Spring Boot: o build pode estar em um subdiretório. Essa validação não é aplicada como exclusão automática aos 50 mil.

## 5. Evidências e contagens por etapa

**Resultado parcial encerrado para a reunião de 17/09/2026 às 14:30.** A consulta informou **95.666 candidatos**; foram efetivamente coletados **42.317 registros únicos**. Após **36.514 exclusões**, restaram **5.803 elegíveis**, todos selecionados provisoriamente.

**A coleta não foi concluída.** O percurso começou pelos repositórios mais antigos e avançou até parte de 2022. As janelas de 2023–2026 não foram coletadas. Por isso, o grande efeito do filtro de atividade nesta base parcial não pode ser generalizado ao universo completo. Os 5.803 são a seleção da parcela coletada, **não o TOP global nem o tamanho definitivo da amostra**.

A diferença de **53.349** entre a contagem inicial da API e os registros coletados não foi excluída pelos filtros: a coleta foi interrompida e o índice do GitHub também é dinâmico.

- **Forks:** 42.317 antes − 1.006 excluídos = **41.311 restantes**.
- **Espelhos:** 41.311 antes − 0 excluídos = **41.311 restantes**.
- **Arquivados:** 41.311 antes − 1.592 excluídos = **39.719 restantes**.
- **Desabilitados:** 39.719 antes − 0 excluídos = **39.719 restantes**.
- **Sem push nos últimos três anos ou sem data válida:** 39.719 antes − 33.728 excluídos = **5.991 restantes**.
- **Templates:** 5.991 antes − 86 excluídos = **5.905 restantes**.
- **Vazios ou sem branch padrão:** 5.905 antes − 2 excluídos = **5.903 restantes**.
- **Materiais educacionais/listas identificados por metadados:** 5.903 antes − 100 excluídos = **5.803 restantes**.

- **Seleção por limite:** 5.803 elegíveis → 5.803 selecionados; zero retirados pelo teto de 50.000.
- **Revisão manual pendente:** 720 elegíveis com sinais ambíguos; permanecem na seleção provisória.
- **Validação técnica desta seleção:** ainda não executada; o uso efetivo de Spring Boot não foi confirmado em todos os candidatos.

As contagens foram conferidas: **42.317 = 36.514 excluídos + 5.803 elegíveis**, sem IDs repetidos nas exclusões e sem sobreposição com os selecionados. O arquivo `collection_status.json` registra explicitamente a interrupção.


Os resultados desta execução ficam em [20260917_apresentacao](Instrumentos/Codigos/Artefatos/selecao_spring_boot/runs/20260917_apresentacao/):

- `count.json`: consulta, data e total informado pela API.
- `population.csv`: candidatos efetivamente coletados, sem IDs duplicados.
- `queries.csv` e `windows.json`: consultas realizadas e janelas concluídas.
- `filter_attrition.csv`: entrada, excluídos, saída e percentual de cada etapa.
- `excluded/*.jsonl`: identificação de cada excluído e motivo.
- `eligible_repositories.csv`: todos os elegíveis ordenados.
- `selected_repositories.csv`: seleção final de até 50.000.
- `flagged_non_software.csv`: candidatos a revisão manual.
- `non_software_reasons.csv`: distribuição dos motivos educacionais/listas.
- `config.used.yaml` e `run_metadata.json`: configuração e dados da execução.
- `report.txt`: resumo do resultado.

A diferença entre o total da API e a quantidade efetivamente coletada deve ser apresentada separadamente: **não é uma exclusão por filtro**. O índice pode mudar durante a coleta.

A base antiga `metadados_spring_boot_50k.csv` usa outro recorte, com `language:Java` e forks já omitidos. Ela foi preservada e não é usada para calcular as exclusões deste novo protocolo. A pasta `_cli_smoke` contém um teste e não deve ser apresentada como resultado empírico.

## 6. Verificações realizadas nesta atualização

Foram executados **11 testes automatizados**, todos aprovados. Além dos testes de filtros e ordenação, foram adicionados testes para falha HTTP, resposta incompleta, paginação interrompida e partição acima do limite da API. O coletor agora interrompe nesses casos, em vez de registrar silenciosamente uma coleta incompleta como concluída. Também foi testada a preservação da data de corte ao refazer a filtragem.

## Como explicar ao orientador

“Primeiro defini uma consulta para contar os candidatos com o tópico Spring Boot. Depois preparei uma coleta com registro das consultas e filtros justificados, que removem duplicações, projetos indisponíveis, inativos e materiais educacionais identificáveis. A seleção acontece depois dos filtros, por estrelas e com desempates definidos. Cada etapa gera os totais antes e depois e uma lista com os motivos das exclusões. A base identifica candidatos; confirmar o uso do framework e revisar materiais ambíguos são verificações adicionais.”
